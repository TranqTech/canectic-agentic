# Canectic BBS v0.9.5a

**Sysop chat and node spy, a guided web experience, configurable themes and menus, notifications, and file attachments on private mail.**

*Written retrospectively in September 2026 from the changelog. The tag shipped on 4 April 2026 without release notes, which is the gap the release script now exists to close. Upgrade instructions below are the current supported path rather than the one documented at the time.*

Seventy-two commits since v0.9.1-alpha.1. This is the release where the sysop stopped being invisible and the web stopped being a second-class way in.

## Highlights

### Node Spy and Sysop Chat

A sysop can now see who is on and talk to them. The NodeSpy dashboard at `/admin/nodespy` shows a live card grid of terminal nodes and web users, refreshed every four seconds, with a live terminal snoop through xterm.js that replays recent output from a ring buffer so you see context rather than starting from blank.

Break-in chat works from the dashboard or from the terminal `nodeSpy` command. On the user's side it opens a DECSTBM split screen with conversation history and an input line, hijacking their input for the duration. If they are mid-door rather than at a menu, the chat queues and fires when they come back.

### Chat on the Web, and Between Users

The same infrastructure reaches web users. A sysop can start a chat with anyone browsing, through a floating overlay that survives page navigation by restoring its history from Redis. Minimise to a badge with an unread count, typing indicators, notification sounds.

User-to-user telegrams use the same path: any authenticated user can message another user who is online, from the Who's Online page. The two modes differ in who may close the window, which is the whole distinction between a sysop breaking in and a user saying hello.

### A Guided Web Login

The web call flow mirrors what a terminal caller has always had: new announcements, last callers, who is online, the wall with an inline post box, and summaries of new messages and files. It is a single AJAX-driven page with no reloads, stages that skip themselves when there is nothing to show, and keyboard navigation throughout.

It triggers on login and offers itself again when an idle session resumes, with escalating insistence: a banner after two hours, a redirect after twenty-four.

### Themes and the Menu System

Terminal colours became a first-class thing a sysop configures rather than a set of constants. Themes live in PostgreSQL with an admin editor organised by colour category, and the cascade runs per-entry override, then per-menu override, then theme default, then handler fallback. A colour bridge carries theme colours into web content containers so the two interfaces agree.

Menus were rebuilt around margin-defined entry regions with automatic column sizing, fill order, vertical centering, and a lightbar mode with full keyboard navigation. Menus can be duplicated, exported to JSON and imported back, which makes a layout something you can share rather than rebuild.

### Art Codes and Size-Aware Art

`@XX@` codes embedded in ANSI and ASCII art are replaced at render time: board name, username, date, node, call and user counts. A width specifier pads or truncates to a field size. Menu codes let art define where entries land, so a menu's layout can come from the art rather than from settings.

Art discovery became size-aware. A file named for an exact terminal size wins, then the closest column match, then the default, and size fit beats format capability. A sixel terminal gets a `.six` companion overlay where one exists.

Web art arrived alongside it, with seasonal overrides: date ranges configured in the admin panel swap in art from a season's directory, seeded with Christmas, Halloween and New Year.

### Notifications

A single notification model with user-targeted and sysop-broadcast types, a bell icon with an unread badge in both nav bars, a full history page, and real-time push over the presence socket. The terminal gets a lightbar reader for the same list.

Producers are wired throughout: the sysop hears about TIC errors, undeliverable mail, AreaFix and FileFix requests and new registrations; users hear about private mail.

### File Attachments on Private Mail

Attachments work across all four transports, which is the part that took the work. Local mail shares one file on disk with references from both sides. Inbound email extracts MIME multipart recursively with base64 and quoted-printable decoding, outbound hands them to nodemailer. FTN parses the file-attach flag from the type-2 packet and, outbound, sets the flag and writes flow file entries for the mailer to pick up. IMAP renders a real multipart BODYSTRUCTURE so a mail client sees them properly.

### QWK for Users

Users can download a personal QWK packet of their subscribed areas and unread private mail, using the scan pointers they already had, and upload a REP packet whose replies post through the normal path. Available on the web and from a terminal menu command with ZMODEM or XMODEM.

### FTN Networking

AreaFix and FileFix let downlinks manage their own subscriptions by netmail, authenticated by a password in the subject line, with `+TAG`, `-TAG`, `%LIST`, `%QUERY`, `%AREAS`, `%HELP`, `%PAUSE` and `%RESUME`.

File requests work in both directions, resolved through a three-layer lookup of magic aliases, then the filebox directory, then the file database, with an auto-generated BBS-wide listing.

Binkp sessions handle a peer advertising several AKAs, grouping the matching connections behind one session with password filtering so an unauthenticated address cannot ride along, and building each connection's outbound list independently.

### Community Content

The wall, bulletins, news files and system statistics all arrived, each reachable from both the terminal and the web, with admin management and access control. News files display ANSI art from door scoreboards or BBS news as a call flow stage.

### Doors

Door collections give many-to-many categorisation with a terminal browser and web cards, returning to the collection after a door exits. The five launch types were consolidated, with the legacy names mapped onto the new set, and all of them now run through the output parser for CP437 conversion and centering.

## Getting Started

```bash
git clone --branch v0.9.5a --depth 1 https://gitlab.tranqsoft.com/drog007/canectic.git
cd canectic
bash setup/install.sh
```

See `docs/sysop/INSTALL.md` for the full walkthrough.

## Upgrading from v0.9.1

```bash
cd /path/to/canectic-source
git pull
bash setup/update.sh /path/to/run-directory
cd /path/to/run-directory
npm install
node src/tools/dbmigrations.js
pm2 restart all
```

Use `update.sh`, not `install.sh`. The install script refuses to update an existing installation, because its update mode replaced `public/` wholesale and destroyed sysop-added door icons, collection images and custom CSS. `update.sh` overlays that directory instead.

New database columns are added automatically by the migration tool. New config keys appear in Admin > Config after restart. Seasonal art directories are created on first run.
