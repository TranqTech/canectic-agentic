# Canectic BBS v0.9.14a

**Fixes Play on the web Doors page, which 0.9.13a broke for nearly every door, and lets your callers play doors on other systems: DoorParty, BBSLink, RLogin door servers and other Canectic boards. Any board on 0.9.13a should take this release.**

Released 2026-09-29 (Handshake).

## Highlights

**Play on the web works again.** On 0.9.13a, a logged-in user pressing Play on the web Doors page had the call end at once for every door not offered to your door server. Terminal callers were not affected.

**Doors on other systems, as doors of your own.** Add DoorParty, BBSLink, an RLogin door server such as a Synchronet game server, or another Canectic board as a door provider, then add its doors. Each becomes an ordinary door entry you put in a collection or a menu, playable in the terminal and on the web. Canectic opens DoorParty's SSH tunnel itself, so their connector program is not needed.

**Door lists.** DoorParty's and BBSLink's door lists come with Canectic: load one on the provider's page and tick the doors you want. A list can also arrive in a file area, by file echo, and be checked every day.

**Your door server offers doors by collection.** Choose which collections other BBSes see and which doors in them are offered, and a remote caller who names no door gets a menu of your collections.

## Upgrading

**From 0.9.13a the update applies itself.** Worth knowing afterwards:

- **Door server doors are now offered by collection.** Each door you had marked Available to Door Server is still offered: it is ticked in every collection it belongs to, a collection holding one is now shown to Both, and one that was in no collection is in a new Door Server collection shown to the door server only. Nothing else in those collections is offered. Check Admin > Doors > Door Collections.
- **A Canectic door server you added on 0.9.13a** keeps working as before. On its page under Door Server, **Load the doors it offers** fills in its door list.

**Coming from 0.9.12a or earlier?** The notes for the releases you skip apply to you too. The Update page lists every one that concerns your board before you update, and they are in the 0.9.13a release notes, https://canectic.tranqsoft.com/releases/0.9.13a/notes. In particular, 0.9.13a closed a hole that let anyone who could reach your web address start your door games, and the door server stays off until you turn on `doorserver_enabled`.

## Changes

### Doors

- Fix: **Play on the web Doors page ended the call at once for every door not offered to the door server,** in 0.9.13a. Your own logged-in users playing in the browser were treated as callers from another BBS, so they could only reach doors offered to the door server, which by default is none. Terminal callers were not affected.
- **The doors your door server offers are now chosen by collection.** A door collection's new **Shown to** setting is This board, Door server or Both, and on a collection shown to the door server each door has an **Offered** switch; doors you add to such a collection are offered at once. A remote BBS's caller who does not name a door now gets a menu of your offered collections and then the doors in the one they pick, through `doorclient.js`, RLogin and another Canectic board alike. A collection shown to the door server only is hidden from your own callers. Changing a collection to include the door server first shows you its doors to choose from. The **Available to Door Server** setting on each door is gone; the doors you had marked are still offered (see Upgrade Notes). A door running on another system can never be offered.
- **New: doors on other systems as doors of your own.** Under Door Server, **Doors on other systems** now takes door providers of three kinds: another Canectic board, an RLogin door server such as DoorParty or a Synchronet game server (through an SSH tunnel where needed, with the server's key recorded on first connect and a changed key refused), and BBSLink. Buttons fill in DoorParty's, BBSLink's and Synchronet's settings. On a provider's page you add its doors, from its door list (below) or by code, and each becomes a door entry with the new **Remote** launch type that you put in a collection or a menu like any other door; web play works the same way. Only logged-in callers at the provider's minimum security (the verified level unless you set one) can use them, and a door on another system is never offered through your own door server. RLogin callers each get a password made once and kept, which DoorParty ties their account to; a caller who changes their username starts again there unless you tick **Keep sending the name a caller first used**. Output is converted for UTF-8 terminals.
- **New: door lists for door providers.** A provider's page can keep the list of doors it offers, so you tick doors instead of typing codes. The list comes from one shipped with Canectic (DoorParty's 170 doors and BBSLink's 36 are included), from a file in a file area (so a list can arrive by file echo), or, for another Canectic board, from the board itself. A **Load** button on the provider's page fills in the list that fits it. Tick doors to add them, remove them from the same list, and switch each door off or on. **Check for changes** shows what a newer list would change before you apply it, and **Check every day** keeps it current with a notification of each change. A door that leaves the list is marked no longer offered and its door entry made inactive, never deleted; the daily check refuses a list that would remove more than half the doors and tells you instead. Canectic never reads anyone's web pages for a list.
- Fix: **Delete on the Door Games page did nothing for a door in any collection,** and said nothing either. The door is now removed from its collections and deleted, and a failure is shown.
- Fix: **unticking Active on a door collection did not switch it off.** The collection stayed active whatever the box said.

### Administration

- **Every admin page now has a card on the admin dashboard.** Door Server (under Doors), Call Flows and Timed Events (under System) and Template Events (under Content) were reachable only from the admin navbar.
